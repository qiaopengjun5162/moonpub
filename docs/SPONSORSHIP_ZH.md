# MoonPub 商业模式：公益核心 + 可选赞助

这份文档只回答一个问题：**MoonPub 靠什么维持，钱会不会改变它的行为和边界。**

它不是融资计划，也不是涨价预告。它把当前已经成立的事实写清楚，让使用者、贡献者和未来的自己都能据此判断「这个项目会不会变味」。

一句话结论：**核心能力永久免费且保持 MIT；赞助是可选的感谢，不换取功能、优先权或服务承诺；不为收入去碰托管凭证、云端代发和绕过平台边界。**

## 一、什么永久免费

下面这些现在免费，将来也不会因为商业模式调整而收费：

- 全部核心命令：渲染、封面、预览、检查、排版审计、发布前质量门、草稿推送、博客导出。
- 全部输入工作流：已有 Markdown、飞书秒记、照片素材，以及后续按同样边界新增的输入源。
- 全部 CLI / Obsidian 插件入口，以及结构化 JSON 协议层。
- 全部排版主题、封面风格、Block 模板与排版配方。
- 完整文档、上手指南、排障经验与演示素材。

MoonPub 的代码以 MIT 许可发布。任何人都可以下载、修改、自用、分发，不需要授权，也不需要付费。

核心规则：**一条能力只要进了「免费核心」，就不能再被挪去当收费点。** 想靠某能力收费，就只能把它做成核心之外的可选附加物，并且不能让免费核心因此变差。

## 二、什么不为了钱去做

用户把文章、凭证和账号交给一个本地工具，前提是信任。以下几条是硬边界，不因为 sponsorship 或商业化讨论而松动：

- **不托管用户凭证。** AppID / AppSecret / token / cookie 默认只留在本机，不上传到我们的服务器——因为根本没有这样的服务器。
- **不做云端代发。** 不提供「把你的公众号交给我们自动发」的服务。最终发布永远由用户在微信后台人工确认。
- **不绕过平台。** 不把绕过扫码、验证码、审核、账号权限或风控当成卖点或付费功能。
- **不承诺 SLA。** 开源工具不承诺可用性、响应时间或专人支持；赞助不改变这一点。
- **不拿用户内容训练或变现。** 用户文章、飞书素材、照片和草稿不被收集、上传或用于任何数据业务。

这些边界同时也是产品定位的一部分：MoonPub 是本地发布副驾驶，不是代运营平台。

## 三、赞助是什么，不是什么

如果这个项目对你有用，而你也愿意支持它继续做下去，可以通过仓库公布的方式自愿赞助。

赞助的定位：

- **是**自愿的感谢与续航，像给喜欢的开源项目买杯咖啡。
- **是**维护者继续投入本地渲染、微信兼容、文档与排障的动力来源之一。
- **不是**购买任何功能、主题、模板或优先权。
- **不是**订阅、会员或服务合同；不附带 SLA、响应承诺或专属支持渠道。
- **不**影响任何人使用核心能力的权利，无论是否赞助，体验完全一致。

换句话说：**赞助买不到任何东西，它只是让这件事能继续做下去。** 如果哪一天赞助看起来像「付费解锁」，那就已经偏离了这份文档。

当前赞助入口以仓库 README / Release 页面实际公布的信息为准；在正式公布前，不虚构收款渠道，也不把任何个人收款码、二维码或账号写进仓库。

## 四、未来可能的可选付费层（现在都不存在）

下面是**方向草案，不是承诺、不是路线图、不是倒计时**。只有核心长期稳定、且明确不违反上面三条边界时，才会考虑其中任何一项：

| 方向 | 可能形态 | 边界 |
| --- | --- | --- |
| 高级模板 / 主题包 | 额外排版主题、封面风格、文章结构模板 | 免费核心的主题与模板继续维护；付费包是新增选择，不阉割已有能力 |
| 批量 / 团队工具 | 多账号配置、批量发布队列、审核记录 | 仍本地运行、凭证留本机、最终发布人工确认；不变成云端 SaaS |
| 工作流服务 | 帮个人和团队配置 Obsidian + MoonPub + 博客 + 公众号 | 按次或按项目收取配置服务工时，不卖「代发」和「包上热门」 |

明确不做：

- 不把已经免费的能力改成收费。
- 不做云端托管 AppSecret、不代用户运营账号。
- 不以自动最终发表、绕过审核或平台风控为卖点。
- 不把赞助包装成会员等级、积分或特权体系。

如果未来真的要引入上面任何一项，先在 issue 里公开说明「收费什么、免费什么、边界怎么保证」，并把结论写回这份文档，再动手实现。先宣布边界，后做事；不反过来。

## 五、怎么支持比钱更重要

MoonPub 现在最缺的不是钱，是真实使用反馈和可持续的维护投入。下面任何一项都比一笔赞助更有价值：

- 用真实文章跑一遍，把排版异常、命令别扭、文档看不懂的地方开成 issue。
- 补一条回归测试、修一个真 bug、改善一处中文 / 英文文档。
- 贡献一套主题、封面风格、Block 模板或排版配方，并说清适用场景。
- 分享你自己的工作流：飞书秒记、照片、读书笔记怎样沉淀成文章。
- 把脱敏后的真实截图 / 录屏补进首次体验证据，让新用户少猜一步。
