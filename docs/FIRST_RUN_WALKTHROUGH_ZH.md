# MoonPub 首次使用向导

这份文档只回答一个问题：

**如果我是第一次接触 MoonPub，现在最省力、最不容易迷路的体验顺序是什么？**

目标不是覆盖全部命令，而是给第一次上手的人一条可以照着走的最短路径。

## 先记住一个原则

MoonPub 当前最适合的理解方式，不是“自动发文机器人”，而是：

**一个本地优先的内容发布副驾驶。**

所以第一次使用时，最重要的不是直接发文，而是先确认这三件事：

1. 你能不能顺利进入一条工作流
2. 你能不能看懂生成出来的草稿和预览
3. 你能不能分清“本地预览”和“微信草稿发布”是两步

## 最推荐的第一次体验顺序

第一次使用时，建议按下面这个顺序走：

1. 先进入插件首页，看整体工作区状态
2. 再选一条素材入口：飞书、照片，或者现有 Markdown
3. 先停在草稿和本地预览，不要一上来就直接推微信
4. 确认你理解结果页和下一步动作后，再进入真实发布链路

## 第 0 步：准备好环境

至少准备这 3 件事：

1. 本机能运行 `moonpub --help`
2. Obsidian 插件已安装并启用
3. 插件设置里已填好 `Articles 根目录`

如果你现在还没有装好插件，先看：

- [../obsidian-plugin/README.md](../obsidian-plugin/README.md)

## 第 1 步：先打开插件首页

在 Obsidian 里执行：

- `打开 MoonPub 首页`

这一步现在不只是状态查询，它已经开始承担插件首页角色。

你会在里面看到：

- 当前推荐入口
- drafts / ready / published 阶段数量
- 推荐下一步动作
- 风险边界
- 首页快捷入口

首页快捷入口目前包括：

- `检查当前文章`
- `预览当前文章`
- `导入最近飞书妙记`
- `导入当前图片目录`

如果你第一次使用 MoonPub，建议永远先从这里进，而不是先记命令。

## 第 2 步：按你的内容来源选入口

### 入口 A：你已经有现成 Markdown 文章

适合你，如果你已经写好了文章，只想检查排版和发布。

推荐顺序：

1. 打开那篇文章
2. 点 `检查当前文章`
3. 点 `预览当前文章`
4. 看懂当前文章工作台后，再决定是否推微信

### 入口 B：你从飞书秒记开始

适合你，如果你当前拿到的是转写、语音记录、碎片素材。

推荐顺序：

1. 在插件首页点 `导入最近飞书妙记`
2. 等插件生成草稿和结果工作台
3. 看结果工作台里的：
   - Inbox
   - Draft
   - HTML 预览
   - 推荐下一步
4. 先点 `打开草稿` 或 `预览草稿`
5. 确认内容没问题后，再考虑 `推进到微信草稿`

第一次使用时，不建议直接走飞书快速 push。

### 入口 C：你从生活照片开始

适合你，如果你现在想把一组照片先沉淀成草稿，而不是继续放在手机里。

推荐顺序：

1. 在 Obsidian 里先打开一张图片
2. 在插件首页点 `导入当前图片目录`
3. 等插件生成照片草稿和结果工作台
4. 先点 `打开草稿` 或 `预览草稿`
5. 确认这组素材被整理得符合你的预期，再继续下一步

## 第 3 步：先停在本地，不急着推微信

第一次使用时，推荐你把目标定在这里：

**成功看到草稿和本地 HTML 预览。**

只要你已经走到这一步，就已经完成了第一次体验最关键的部分。

因为这说明：

- 入口是通的
- 素材能进系统
- 草稿能生成
- 预览能打开
- 你开始理解 MoonPub 的节奏了

## 第 4 步：第二次再进入真实发布

等你第一次已经习惯了“素材 -> 草稿 -> 预览”这条节奏，再开始进入：

- `push --render`
- `ship`
- `configure`
- 微信后台预览

也就是说：

- 第一次体验，目标是“看懂流程”
- 第二次体验，目标才是“真实发布”

## 如果你只想记住一条最短建议

第一次使用时，只记住下面这 4 步就够了：

1. 打开 `打开 MoonPub 首页`
2. 从首页选飞书、照片或当前文章入口
3. 先停在草稿和本地预览
4. 确认看懂结果页后，再进入微信发布
