写完，

Markdown 进，公众号草稿出。
排版、封面、原创赞赏设置全自动，最后那一下「发表」永远留给你。

v0.4.28 2026-11-26 github.com/qiaopengjun5162/moonpub

它是什么一条命令，把一篇稿子送到「就差你点发表」

STEP 1

你写

在电脑上用 Markdown 写正文。任何编辑器都行，Obsidian、VS Code、纯文本。

STEP 2

它干活

排版、生成封面、上传图片、设置原创/赞赏/留言，把草稿推进公众号后台。

STEP 3

你发表

在手机上看一遍预览，确认没问题，自己按下发表。它绝不替你做这一步。

一句话：它替你干重复的活，不替你做决定。

全部在你自己的电脑上跑。文章、配置、公众号凭证都不上传任何服务器。

先看效果四条命令，不需要公众号账号，不联网

$ moonpub init --yes
$ moonpub new "我为什么开始每天写点东西"
$ moonpub render Articles/drafts/我为什么开始每天写点东西.md
$ moonpub preview Articles/drafts/我为什么开始每天写点东西.md
# 浏览器打开成品，全程不碰微信

这四条命令只读写本地文件。没装也没关系，后面讲怎么装。

为什么值得用一篇公众号，手动排版要多久

环节手动做用 MoonPub
排版样式（字号、间距、引用块）20–25 分钟，每篇重来改一个词，3 秒
封面图开设计软件 5–10 分钟一条命令，30 秒
后台四项设置（原创/赞赏/留言/来源）每次手点，容易漏推送时自动做完并复核
多篇风格一致靠记忆，经常不一样同一个主题名，永远一样
合计约 30–40 分钟约 3 分钟

省下的不是创作时间，是每篇都要重来一遍的重复劳动。

演示 · 装上到建好一篇第 1–4 步，四条命令

下载解压就能用——不需要装 Rust 或 Node，也不用懂编程。init 建配置，new 建文章骨架。

演示 · 一篇文章长什么样第 5 步

  • 最上面三行是信息：标题、摘要、主题。
    摘要会出现在公众号列表里
  • :::intro 是开头引言块，带一条色带。
  • :::summary 是结尾总结卡。
  • 中间空着的地方，随便写。就是普通段落。

不用学 Markdown。记住 ## 是小标题、- 是列表，够用了。

  • 一次 render 产出成品网页和草稿数据。
  • 改了内容？再 render 一次，成品就更新。
  • 图片自动检查：找不到图会报错停下，不会静默漏图。

排版不是设计，是匹配31 套主题，改一个词换一套

同一篇文章、同一段文字，只改 theme 后面一个词。挑不准就 blueprint（技术）或 porcelain（通用），不会出错。

封面也不用开设计软件22 种风格，从文章信息里长出来

同一篇文章，四种风格，命令只差一个 --style。

缩到列表里 96×66 才是真考验。纯白那张糊成一片，深色和渐变还站得住。

22 种封面风格 × 31 套正文主题，一套组合够用很久。封面还能用 AI 底图，只是那步要自己的模型 key。

一条命令，做完六件事第 9 步

  • 开留言、设创作来源
  • 正文和图片一起上传
  • 保存草稿，拿到 media_id
  • 重载编辑器，四项设置逐项复核真的落库
  • 把预览发到你手机微信
  • 然后停手——发表留给人

八天里发了 14 个版本（v0.4.15 → v0.4.28）。每次发版必须过 CI、过资产校验，下载下来验 sha256 和版本号才算完。

优势四条，每条都能当场验证

01 本地优先

文章和凭证不出你的电脑

没有云端账号，没有服务器替你保存 AppSecret。断网也能排版、能预览。

02 人工兜底

永远不替你点发表

自动化到草稿为止。平台审核、扫码、验证码这些，它不绕。

03 可版本管理

文章就是纯文本

git 能管、能对比、能回滚。改坏了退回上一版，不用问任何平台。

04 真的快

一篇三分钟

排版、封面、后台设置三件最烦的事，都在命令里。

劣势和边界这些是设计选择，不是待修的 bug

  • 只做公众号。多平台（WordPress / Ghost / 静态博客）在 v0.7 路线里，现在没有。
  • 依赖微信后台界面。微信改版可能让「设原创/发预览」这些步骤软失败，需要更新版本。
  • 登录态会过期。cookie 会话失效要重新扫一次码。
  • 没有图形界面。命令行对非技术用户有门槛——虽然只有九条命令。
  • AI 写作要自备 key。接大模型写稿/润色不是核心路径，且结果要人工审。
  • 不是成熟商业产品。Beta 阶段，定位是「技术用户可试用」。

所以它适合：自己写、自己发、每周要发几篇的人。不适合：想找人代运营、想一鍵群发多平台的团队。

和别的做法比同一件事，四种干法

做法排版封面后台设置主要代价
手动排（后台直接排）每篇重来设计软件手点，易漏每篇 30–40 分钟
第三方排版编辑器模板丰富要另做仍要手点内容上传到别人服务器
Notion / 笔记导出样式会丢没有全手点排版在微信里常崩
MoonPub31 套主题，改一个词一条命令自动做完并复核只支持公众号，要会用命令行

不是替代排版编辑器——它管的是「从稿子到草稿箱」这段重复劳动。

接下来做什么路线公开在仓库里，硬边界写在文档里

v0.5 · 插件化核心

把能力变成接口

发布器、渲染器、封面主题、导出目标、钩子都做成可扩展接口，为多平台打地基。

v0.6 · Obsidian 正式化

在笔记里直接发

当前笔记一键渲染/预览/出封面，状态看得见，触达微信的动作要显式点击。

v0.7 · 多平台

先静态博客，再 WordPress

Zola / Hugo 导出 → WordPress REST API → Ghost。只接有官方 API 的平台。

v1.0 · 商业化（草案）

核心免费不变

可选付费层与模板市场只是方向草案，未承诺。硬边界：不托管凭证、不代发、不绕审核。
