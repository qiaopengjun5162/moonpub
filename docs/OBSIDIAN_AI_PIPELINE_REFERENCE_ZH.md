# Obsidian + AI 内容生产线参考

这份记录来自用户提供的“Obsidian+AI 如何搭一条内容生产线”文章截图文本，只作为 MoonPub 产品收口参考，不复制原文，不把 MoonPub 改成通用知识库或 Obsidian 教程项目。

## 可吸收原则

- 本地 Markdown 是核心资产：素材、草稿、发布记录都应优先落成真实 `.md` 文件，避免被平台或 App 绑定。
- 先收件箱，后分类：新来源先进入 Inbox，再由工作流整理成草稿、素材或归档，不要求用户一开始设计复杂目录。
- 用户只需要知道下一步：第一次使用应尽量减少概念负担，优先给“现在点哪里、下一步做什么”的引导。
- AI 应做素材整理和草稿辅助：AI 可以帮助分类、摘要、关联、生成选题或草稿，但不要替用户自动最终发布。
- 内容资产要可追溯：AI 生成的观点、摘要和草稿应尽量保留来源路径或原始材料位置，方便回看。
- 少装插件，先跑通主线：MoonPub 的插件首页也应先服务当前文章、飞书、照片和微信草稿四条主线，不急着扩成按钮墙。

## 映射到 MoonPub

| 文章里的做法 | MoonPub 当前对应 |
|---|---|
| `raw/` 原始材料 | `Inbox/Feishu/`、`Inbox/Photos/` 和未来公开 URL 归档 |
| `wiki/` AI 整理后的知识页面 | `Articles/drafts/` 可编辑草稿与后续主题索引 |
| 一条素材先写一句自己的理解 | `draft-from-inbox` / `intake ... --draft` 的事实约束和去 AI 味 |
| AI 帮忙整理、找关联、生成选题 | 当前 AI draft / polish / expand，后续可扩只读 `draft-audit` |
| 发布日历和状态字段 | `Articles/drafts` / `ready` / `published` 与 `status --json` |
| 月度体检 | 后续可以做本地只读 workspace audit，不触发微信 API |

## 暂不进入主线

- 不把 MoonPub 改成 Obsidian 教程或通用知识管理 App。
- 不默认接管整个 Obsidian vault，也不默认扫描用户所有私人笔记。
- 不内置 Claude Code / Copilot / Web Clipper 的安装与账号流程。
- 不自动删除、改写或重排用户素材库。
- 不把“AI 自动整理”做成无人值守发布；微信草稿推进和最终发表仍需显式确认。

## 近期可落地动作

- 插件首页继续强化“当前文件上下文 -> 推荐路径 -> 下一步”的表达。
- 飞书和照片链路继续保持 `--draft --preview` 作为默认安全起点。
- 文档第一屏可以更明确地讲 MoonPub 的价值：把零散素材变成本地可编辑草稿，再安全推进到微信公众号。
- 未来如果做内容资产层，优先做只读索引和证据链，不先做自动分类大迁移。
