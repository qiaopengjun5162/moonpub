> **项目**：MoonPub —— 用 Rust 写的公众号发布副驾驶
> **仓库**：github.com/qiaopengjun5162/moonpub

公众号发出去之后，很多人还有第二个地方要发：自己的博客。正文再复制一遍、删掉微信那套标记、图片重新传一次——一套下来二十分钟，比写文章还烦。

`moonpub export` 把这件事变成一行。我第一遍跑的时候以为五分钟能搞定，结果导出的东西四处都不对，后面会一条条说。

## 先看它吐出来什么

拿一篇带两张图的文章试：

```bash
moonpub export writing/articles/14-配图.md
```

```
exported
  /path/to/你的博客/content/2026-11-26-14-配图.md
  images: 1 copied to static/images/
```

三行，三件事：Markdown 落在哪、图被搬到了哪、搬了几张。

打开那个文件，开头是这样：

```toml
+++
title = "MoonPub 文章里的图，怎么放才看得清"
description = "同一篇文章，图没放对，读者在手机上看到的是一片马赛克。…"
date = 2026-11-26T00:00:00Z
+++

<!-- more -->

> **项目**：MoonPub —— 用 Rust 写的公众号发布副驾驶
```

`+++` 中间那几行是 Zola 要的格式（静态博客生成器的一种），`<!-- more -->` 是「首页摘要到此为止」的分界。你不需要背这两个记号，它们由命令写。

## 先告诉它博客在哪

第一次用要配两行。打开 `moonpub.toml`：

```toml
[blog]
kind = "zola"
root = "/你的博客路径"
# category = "随笔"
```

`root` 指的是博客仓库的根目录——不是 `content/` 子目录，是它的上一层。命令会自己在下面建 `content/` 和 `static/images/`。

`category` 那行默认注释着。想给导出的文章统一归一个分类，就把 `#` 去掉改成你要的词。**留空不是省略，是不写分类**——不会替你猜一个。

没配 `root` 就跑，会得到这么一句：

```
Error: missing value for blog.root in config
```

它没说「博客」两个字，但 `blog.root` 就是那个位置。

## 一条命令，四个字段都有来源

这是这条命令最省事的地方：**导出的每个字段，都从你文章里已有的东西取，不需要再填一遍。**

| 导出到博客的 | 取自哪 |
| --- | --- |
| 标题 | 文章抬头那行 `title:` |
| 摘要 | `digest:`（就是公众号那条摘要） |
| 日期 | `date:`；**没写就取文件的最后修改时间** |
| 分类 | `moonpub.toml` 里的 `[blog] category` |
| 正文图 | 正文里引用的本地图片，复制进博客的 `static/images/` |

摘要那条值得多说一句：你为公众号写的那段 `digest`，博客直接用，不用重写。写公众号摘要时想着「读者为什么该点开」，那正是博客搜索结果里要显示的那句话。

## 我第一遍跑出来的四个错

这四个我第一遍全撞上了，而且**命令退出码是 0，一句警告都没有**——不打开导出结果根本发现不了。

**第一个：日期是 1970 年，文件名也是。**

```
exported
  /path/to/你的博客/content/1970-01-01-14-配图.md
```

那篇没写 `date:`，于是它回落成了一个默认值。问题是 Zola 按日期排文章，**所有文章会一起掉到时间轴最前面**，博客首页看起来就像刚建站。现在没写日期会取文件的修改时间，那才是你用得上的那个数。

**第二个：摘要是标题的复读。**

`description` 和 `title` 一字不差。搜索结果显示出来就是同一句话出现两遍，白占一行。现在优先用 `digest:`，没有才取正文第一段（会跳过开头的引用块、图片、代码块——那些当摘要都是半截话），最后才回落到标题。

**第三个：分类写着「读书」。**

那篇文章讲配图，跟读书没关系。这是个写死的值，现在只认配置文件里的 `category`，没配就不写。

**第四个：图片全是断链。**

正文里写的是 `../assets/2026-11-26-images/01-width-compare.png`，导出后原样抄了过去。这个路径相对的是**你的写作目录**，放进博客仓库的 `content/` 里，它指向一个不存在的位置——博客上线后每张图都是破图。

现在图片会被复制进 `static/images/`，正文里的引用改成 `/images/01-width-compare.png`。同一张图被引用两次只搬一次；两篇文章各有一张 `cover.png` 且内容不同时，第二张会存成 `cover-1.png`，不会互相覆盖。

引用的图不存在时它会直接报错，不会跳过：

```
Error: .../assets/没有这张.png: export 需要这张图存在：
Zola 的 content 目录里写相对路径会变成断链
```

报错比跳过好。跳过的话你要等到博客上线、读者看到破图才知道；报错只花你改一行 Markdown。

## 卡住了怎么办

**`missing value for blog.root in config`** — 没配博客路径。看上面那两行配置。

**报某张图不存在** — 正文里那张图在磁盘上真的没有。要么路径写错，要么图还没做。这种情况 `moonpub preflight` 也会提前告诉你，不用等到导出。

**导出的日期不对** — 文章抬头没写 `date:`，用的是文件修改时间。想固定就加一行 `date: 2026-11-26`。

**博客里图片还是不显示** — 先看导出输出有没有 `images: N copied` 那行。没有就说明正文里的图片不是本地相对路径（比如已经是 `https://` 外链），命令不会去动它。另外确认博客的 `static/images/` 是你图片目录——Zola 默认是这里，改了配置的话路径也要跟着改。

## 它不管的三件事

**第一，不管「发表」。** 导出只是把文件写到博客目录，`git add`、`commit`、`push`、等托管平台构建，这些还是你。和公众号那一步一个道理：机器做到「文件就位」，拍板的那一下留给人。

**第二，不管博客长什么样。** 导出的 Markdown 用的是你博客现有主题的渲染规则，排版长什么样取决于主题，不取决于 moonpub。换句话说：公众号那边的排版是 moonpub 做的，博客这边它只负责把内容搬过去。

**第三，只切掉公众号的页脚，别的都不动。** 如果你把公众号文章粘回 Markdown 时带上了文末那段关注图和引导语（`---` 后面那一块），导出会把它切掉——博客读者不需要扫码关注你的公众号。但正文里「点击上方蓝字」「长按识别」这类句子会原样留着，读起来很怪，值得手动删一遍。我每篇导出后都会扫一眼结尾。

## 什么时候值得用

如果你只发公众号，这条命令对你没用，忽略它就行，不影响其他任何功能。

如果你同时在维护博客，它省下的是重复劳动里最枯燥的那部分：复制、去标记、传图、填日期。**写作本身没变，只是同一篇稿子不用再伺候两个地方。**

这篇就到这里。工具的意义不是让你多写点，是让你少做点重复的。
