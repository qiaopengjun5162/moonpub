两套材料，同一份内容，按场合挑一套：

| 版本 | 文件 | 页数 | 时长 | 什么时候用 |
| --- | --- | --- | --- | --- |

# 第 1 部分 · 11 页版（10–11 分钟）

时间分配：P2 / P3 各 1 分钟，P4 40 秒，P5–P8 各 1.5 分钟，P9 1.5 分钟，P10 40 秒，P11 30 秒。开头结尾各留 20 秒缓冲。

## P1 封面（30 秒）

**先给结论：这是一个把你从「排版半小时」里捞出来的小工具。写完，就已经排好版了。**

- 今天讲三件事：它解决什么问题、怎么用、值不值得你用。不讲代码怎么写。
- 一句话划清边界：**自动化到草稿箱，最后那一下「发表」永远是人点。**
- 版本口径：讲「最新版 v0.4.28」，别说「很稳定」这种形容词。

> 只有 30 秒的场合：只讲标题和最后那句边界。

## P2 它是什么（1 分钟）

**三步：你写、它干活、你发表。**

- 你写：Markdown，任何编辑器都行，Obsidian / VS Code / 纯文本。
- 它干活：排版、封面、图片上传、后台四项设置（原创 / 赞赏 / 留言 / 创作来源），推进草稿箱。
- 你发表：手机看预览，自己按。
- 补一句设计的取舍：**全部在你自己的电脑上跑，文章和公众号凭证不上传任何服务器。** 这不是宣传话术，是它没做网页版的原因。

> 预设提问「那算自动发布吗」——不算，也不打算算，原因在 P9 讲。

## P3 为什么值得用（1 分钟）

**省下的不是创作时间，是每篇都要重来一遍的重复劳动。**

- 手动排一篇：排版 20–25 分钟 + 封面 5–10 分钟 + 后台设置 3 分钟，合计 30–40 分钟。
- 用 MoonPub：约 3 分钟，时间主要花在等内容渲染和检查上。
- 比「单篇快」更值钱的是**一致性**：十篇文章样式永远一样，因为它们指向同一个主题名。

> 可以问一句「在座写过公众号的，排版一般花多久」，然后把答案接回这张表。

## P4 九步全景（40 秒）

**从零到草稿箱九步，第一次约 10 分钟，之后每篇从第 4 步开始。**

- 这张图只是地图，不要逐条念。
- 点一下这个设计：**每一步结尾它都打印下一条该敲的命令（`next: …`），所以不用背命令。**

> 快到下一句：装、体检、初始化、建一篇，下面四张图就是第 1–4 步。

## P5 演示 · 装上到建好一篇（1.5 分钟）

**下载解压就能用，不需要装 Rust，也不需要装 Node。**

- `moonpub --version` 能出版本号，就等于装好了。
- `moonpub doctor` 会做体检，并直接把「下一条该敲什么」告诉你——出问题不用猜。
- `init --yes` 建配置，`new "标题"` 建文章骨架，骨架里 title / digest / theme 三行已经填好样例。

> 网络不稳就别现场下载，直接用已经装好的机器演示，一句话带过「装法就是解压 + 移到 PATH」。

## P6 演示 · 一键出成品（1.5 分钟）

**`render` 一次，产出成品网页和草稿数据；改完内容再 render 一次，成品就更新。**

- 左边就是 render 出来的成品：引言块、正文、结尾总结卡，全是自动的。
- 强调图片会被检查：**找不到图会报错停下，不会静默漏一张图**——静默失败是排版工具最坑人的地方。
- 顺带说：成品是本地 HTML，断网也能看、也能发给别人。

## P7 排版和封面，都是一句话（1.5 分钟）

**排版不是设计问题，是匹配问题。**

- 31 套主题，改 `theme` 后面一个词就换：左边四张图是同一篇文章、同一段字，只有主题不同。
- 挑不准就给两个保底：技术文用 `blueprint`，通用文用 `porcelain`。
- 封面同理，`--style` 换一个词，22 种风格从标题和摘要里长出来。
- 这张图最值得讲的是右边那列缩略图：**缩到列表里的 96×66 才是真考验**，纯白那张直接糊掉，深色和渐变还站得住。这条经验对所有写公众号的人都成立，跟用不用这个工具无关。

## P8 推送：一条命令，做完六件事（1.5 分钟）

**它做六件事，而且每一件都复核过。**

- 逐条：开留言设创作来源 → 正文图片一起上传 → 保存草稿拿到 media_id → 重载编辑器逐项复核 → 把预览发到你手机 → 停手。
- 重点讲第四件：**它不是点完就算，会把编辑器重新加载一遍，读后台真实状态确认四项设置真的落库。** 点成功不等于存成功。
- 提一句 media_id：以后要改这篇，用它定位。
- 收口：它停在草稿箱，发表留给人。

> 预设提问「安全吗」——走的是你自己账号和浏览器的正常后台操作，不刷接口、不群发、不自动发表；推的是草稿不是发布。

## P9 优势，和它的边界（1.5 分钟）

**这一页我主动讲缺点，因为不讲你也会发现。**

- 左边四条优势，每条都能当场验证：本地优先、人工兜底、可版本管理（文章是纯文本，改坏了 `git checkout`）、真的快。
- 右边五条缺点照念：只做公众号 / 依赖微信后台界面，改版可能要更新 / 登录态会过期要重扫码 / 没有图形界面 / Beta 阶段。
- 底部那行是「凭什么信它」：**1055 个自动化测试，行覆盖 85.0%，低于门槛 CI 直接红；五个平台每个资产带 sha256；依赖漏洞零，每周一自动扫。** 数字不要说「很稳定」这类形容词。
- 补一句定位：**它适合自己写、自己发、每周几篇的人。** 团队协作、多平台分发，现在都不擅长。

> 主动讲缺点换来的是后面提问环节的可信度，不要跳过这页。

## P10 接下来做什么（40 秒）

**路线公开在仓库里，硬边界写在文档里。**

- v0.5 插件化：发布器、渲染器、封面主题做成接口，为多平台打地基。
- v0.6 Obsidian 插件正式化：在笔记里直接渲染、预览、出封面。
- v0.7 多平台：先静态博客（Zola / Hugo），再 WordPress，再 Ghost，只接有官方 API 的。
- v1.0 商业化只是草案：核心 MIT 免费不变，**不托管凭证、不代发、不绕审核**。

> 被问「会不会收费」：照这条答，核心免费，付费层只是方向，未承诺。

## P11 现在就能试（30 秒）

**不需要注册，也不需要公众号账号，五分钟能看到成品。**

- 五条命令在左边，`init --yes` → `new` → `render` → `preview`，全在本地，一次网络请求都没有。
- 仓库 `github.com/qiaopengjun5162/moonpub`，Releases 五个平台，文档 `docs/COMMANDS_ZH.md`。
- 卡住就跑 `doctor` 和 `preflight`，它们会告诉你缺什么。

**谢谢，随便问。**

# 第 2 部分 · 18 页版（18 分钟）

## P1 封面（1 分钟）

**先给结论：这就是一个把你从「排版半小时」里捞出来的小工具。**

## P7 演示：一篇文章长什么样（2 分钟）

# 可能被问到的问题

| 问题 | 怎么答 |
| --- | --- |
| 会不会被微信封？ | 它用的是你自己的账号和浏览器会话，走的是后台正常操作，不刷接口、不群发、不自动发表。风险和你手动排版发布一样。 |
| 为什么不做网页版？ | 凭证不出本地是硬约束。做网页版就得托管密钥，那是这个项目明确不做的事。 |
| 支持小红书 / 知乎吗？ | `cards` 能切竖版卡片，但正式多平台发布在 v0.7，只接有官方 API 的平台。 |
| AI 写稿能代替我吗？ | 那些命令要你自己的模型 key，且结果要人工审。它们不是核心路径。 |
| 我不用命令行怎么办？ | 现在是门槛，Obsidian 插件（v0.6）就是为了这个。 |
| 为什么一个人维护还敢用？ | 不是让你信我，是让你看门禁：测试数、覆盖率下限、五平台 sha256、每周依赖扫描，全在 CI 里跑。 |
| 排版会不会千篇一律？ | 31 套主题 + 22 种封面风格，够挑；一致性是优点，不是缺点。 |
