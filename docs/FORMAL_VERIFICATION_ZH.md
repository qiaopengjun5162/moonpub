# 形式化验证对 MoonPub 值不值得——决策记录（2026-11-28）

这份文档回答一个问题：**MoonPub 该不该上形式化验证（Lean 4 这类）？上了效果如何？**

结论先给：**现在不该上 Lean 4。** 但项目里确实有三个「本该被证明」的不变量，已经用零依赖的属性测试锁住并进了 CI。下面是我实际动手做过的两套实验、成本数据和判断依据，不是纸面推演。

## 1. 一句话说清形式化验证是什么

普通测试是「举例子」：我试了 100 种输入，都对，**所以大概**对。

形式化验证是「给证明」：我写下「对所有输入 X，都有性质 P(X)」，然后用机器逐条检查推导过程，**所以确实**对——除非命题本身写错了。

代价是：命题必须精确到没有歧义，而且证明过程机器不认人情，一行推不过去就是过不去。

## 2. 本项目的代码构成：只有一小块「值得证」

| 指标 | 实测 |
| --- | --- |
| `src/` 总行数 | 43,382 |
| 其中 `#[cfg(test)]` 之后的测试代码 | 18,956（43%） |
| 实际被测代码 | 约 24,400 行 |
| IO / 网络 / 浏览器 / 文件调用点 | 329 处 |
| 纯函数与类型定义 | 559 个 |

形式化验证擅长的是**纯函数 + 强不变量**：给定输入，输出必须满足某条性质，且不碰外部世界。

`src/` 里符合这个形状的核心其实很窄，真正有「微妙算术」的只有三处：

1. `wechat::bound_digest` —— 摘要截断，要保证 UTF-16 码元数不超过微信的 120 上限；
2. `timefmt::civil_from_days` / `civil_from_secs` —— 手写的 Hinnant 民用历换算（项目刻意不引 chrono）；
3. `html::escape` —— 正文元字符转义，要保证输出里没有裸 `<` / `>`。

其余 2 万多行是**模板拼接、配置解析、WeChat HTTP 调用、CDP 浏览器自动化**。这些不是「逻辑微妙容易写错」，而是「外部世界随时会变」——微信后台改版、登录态三天过期、图片格式限制。形式化验证对这类问题一点用都没有：你可以证明「发请求的代码正确」，但证明不了「微信明天不改接口」。

## 3. 实验一：用 Lean 4 真的证一遍

Lean 4.27 本机已有，我照着 `bound_digest` 手抄了一个模型并证了两条定理：

- `boundDigest_units_le`：对**任意**字符列表，截断结果的 UTF-16 码元数 ≤ 120。
- `boundDigest_is_prefix`：截断只删尾巴，结果是原文前缀，不会凭空插字。

证明文件在 [`verification/lean/BoundDigest.lean`](../verification/lean/BoundDigest.lean)，78 行（含注释），编译 1.7 秒。

关键校验：`#print axioms` 显示两条定理只依赖 `propext` 和 `Quot.sound`——这是 Lean 内核的标准公理，没有 `sorry`、没有 `admit`、没有自定义 `axiom`。也就是说证明是干净的，不是「假装证了」。

**但这里有一道过不去的坎**：Lean 证的是我手抄的那个 `takeUnder` 模型，不是 Rust 里的 `bound_digest`。Rust 那边改一行，Lean 完全不知道，证明照样「成立」。要弥合这道缝，得用 Aeneas / Charon 把 Rust 翻成 Lean，或者改用 Verus 直接在 Rust 子集里写证明——都是另一个量级的工程。

## 4. 实验二：同一批不变量，改用属性测试（已进 CI）

既然 Lean 有模型鸿沟，我把同样三条不变量写成了跑在**真实代码**上的属性测试：`src/property_tests.rs`，11 个测试，零新增依赖（自带 40 行 xorshift64，种子写死可复现）。

| 不变量 | 用例数 | 手段 |
| --- | --- | --- |
| 摘要 UTF-16 ≤ 120 | 20,000 | 随机（混入 2 码元 emoji） |
| 摘要边界 119/120/121 精确 | 边界值 | 定点 |
| 截断只删尾巴（前缀性质） | 20,000 | 随机 |
| 摘要处理幂等 | 5,000 | 随机 |
| 日期换算互逆（完整格里历周期） | 146,097 | 穷举逐日 |
| 日期换算互逆（epoch 之前） | 146,097 | 穷举逐日 |
| 每年首日/末日互逆 | 20,000 | 穷举 |
| 日期字典序 = 天数序 | 73,050 | 穷举 |
| 一天之内任意秒不跨日 | 20,000 | 随机 |
| 转义后无裸尖括号 | 20,000 | 随机 |
| 转义可无损还原 | 20,000 | 随机 |

合计约 **51 万条断言，跑完 0.8 秒**。

### 为了确认这些测试「真的能失败」，我做了变异测试

测试全绿不等于测试有用——如果改坏代码它还是绿的，那它就是装饰。故意把实现改坏，看能不能抓住：

| 变异 | 后果 | 结果 |
| --- | --- | --- |
| `bound_digest` 的 `<` 改成 `<=` | 摘要最长 121 码元，`push` 被微信拒 | **抓到**，2 个测试红 |
| `civil_from_secs` 的 `div_euclid` 改回 `/` | epoch 前日期整体错一天 | **第一轮漏了** |
| `escape` 删掉 `<` 分支 | 正文尖括号变成标签，整段被吞 | **抓到** |

第二条值得单独说：**第一轮它没被抓到**。原因是我只测了 `civil_from_days`（接收「天」），没测 `civil_from_secs`（接收「秒」并做除法），变异正好落在没覆盖的那个函数上。补上「一天之内任意一秒必须落在同一天」这条性质后才抓住。

这件事本身就是这次调研最有用的一条结论：**命题写在哪里、作用在哪个函数，比用什么工具重要得多**。Lean 4 再强，你没想到要证那条性质，它也不会替你想。

## 5. 为什么现在不该上 Lean 4

| 理由 | 具体事实 |
| --- | --- |
| **模型鸿沟** | Lean 证的是手抄模型，Rust 改了它不知道。守住真实代码靠的还是属性测试。真要弥合得上 Aeneas / Verus，工程量大一个数量级。 |
| **失败模式不匹配** | 项目线上问题全是「微信后台改版、cookie 三天过期、图片格式不收、CI 没跑 job」，没有一条是「算法逻辑微妙错误」。形式化验证对这些零覆盖。 |
| **成本不划算** | 证一条 75 行的小定理顺利也要半天；证 `civil_from_days` 的互逆性（Hinnant 算法）是公认的硬活，几百到上千行证明。同样的时间拿去补 `cdp.rs` / `push_browser.rs` 的覆盖，或做 `PublishTarget` 接口，收益高得多。 |
| **工具链负担** | elan + 工具链本机占 5.3 GB，单次工具链下载 138 MB。项目现在的 CI 没有 Lean，加进去意味着五平台 job 全部要装 Lean。 |
| **读者成本** | 这个项目刻意不引 chrono 就是为了「一份算法、一处闰年」。Lean 证明对非 Lean 读者等于不可读，出了事没人能维护——而维护不动的证明，比没有证明更危险（它给人虚假的安全感）。 |

## 6. 如果哪天真要做，正确的顺序

不是「上 Lean 4」，而是按这个顺序挑：

1. **Kani**（bounded model checking，直接验 Rust 代码，无模型鸿沟）——最适合 `bound_digest` 这种纯函数，写 `#[kani::proof]` 即可，不用另抄模型。
2. **Verus**（在 Rust 子集里写前置/后置条件，SMT 自动证）——适合必须写进生产代码的契约，但要把被证函数改写成 Verus 方言。
3. **Aeneas / Charon + Lean 4**——只有当你需要「对任意输入、机器检查过」的定理，且能接受翻译层时，才轮到它。
4. 现在这条路（**属性测试 + 变异测试**）——成本最低，守住真实代码，已在 CI 里跑。

## 7. 什么时候重开这个话题

满足任意一条再谈形式化验证：

- 出现**纯算法型核心**：比如自己实现 Markdown 解析器状态机、排版断行算法、增量渲染 diff——这类「输入空间大、错一个字符就全错」的东西值得证。
- 出现**资金或权限相关的判定**（例如赞助/授权校验），错一次的代价远高于证明成本。
- 属性测试抓不到的那类 bug 反复出现：说明要的是「对所有输入成立」，而不是「多试几个例子」。

现在三条都不满足。

## 8. 怎么复现

```bash
# 属性测试（在 CI 里）
cargo nextest run --all-features property_tests

# Lean 证明（不在 CI 里，需本机装 Lean 4）
cd verification/lean && lean +v4.27.0 BoundDigest.lean
```

Lean 样例**故意不接进 CI**：它是决策记录和教学样例，不是质量门禁。代码一旦大改，它可能悄悄失真——以 Rust 属性测试为准。
