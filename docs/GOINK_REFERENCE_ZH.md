# Goink 参考结论

这份文档记录 MoonPub 对 [sigpanic/goink](https://github.com/sigpanic/goink) 的参考结论。

## 它解决什么问题

Goink 是本地优先的 AI 长篇写作系统。其核心是结构化创作状态、可确认的正文修改、本地语义检索和写后自检，不是公众号发布工具。

MoonPub 的目标不同：把作者已有的 Markdown、飞书妙记和照片素材整理为可审查草稿，再推进到公众号草稿。因此只吸收适合本地发布工作流的原则，不复制产品形态或代码。

## 可以吸收

### 1. 修改必须可审查

MoonPub 现有 `polish` / `expand` 会直接写回文章。后续优先补“建议稿或 diff -> 人工确认 -> 写回”的保守路径，尤其适用于飞书口述稿和照片草稿。默认不应让 AI 覆盖作者原文。

### 2. 来源与处理记录可追溯

`InboxMetadata` 已记录 `source`、`external_id`、`source_title` 和时间。后续应继续记录草稿从哪个 Inbox、通过哪个处理动作产生，而不是把素材和 AI 改写过程变成不可解释的黑箱。

### 3. 发布前后有明确检查点

MoonPub 已有 `layout-audit`、`preflight`、微信后台人工确认。后续可补只读 `draft-audit`：检查是否保留来源、是否有未确认 AI 改写、封面和 HTML 是否齐全；它不得调用微信 API、打开浏览器或自动发表。

### 4. 本地优先与显式确认

本地 Markdown 继续是唯一正文资产。AI 调用、草稿写回、微信草稿推进都必须由显式动作触发；最终发表始终保留人工确认。

## 不应吸收

- 不把 MoonPub 变成长篇小说状态管理系统，不引入角色、伏笔、世界观、读者认知等领域模型。
- 不为近期路线引入本地向量数据库、ONNX 模型或语义检索基础设施；当前瓶颈是首次体验和发布可信度，不是搜索能力。
- 不复制 Goink 的 Go/Wails/React 实现。Goink 使用 AGPL-3.0，MoonPub 为 MIT，必须保持实现与许可隔离。
- 不做 AI 自主写回、自动维护或自动最终发表。

## 后续优先级

当 v0.4.2 的真实首次体验证据与 release 资产门禁完成后，优先顺序是：

1. `polish` / `expand` 的可审查建议稿或 diff。
2. 只读 `draft-audit`，复用现有本地质量门。
3. 草稿处理记录的最小元数据，不引入数据库。

在此之前，继续优先补齐插件首页、飞书和照片的真实首次体验证据。
