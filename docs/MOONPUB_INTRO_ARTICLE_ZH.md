# 做一篇文章，自动跑到手机预览

:::meta-strip
date: 2026-07-14
mood: 自动完成重复劳动，保留作者确认

MoonPub v0.4.2：一个本地优先的内容发布副驾驶。
:::

:::intro
我想做的不是“又一个写作工具”，而是一条尽量不用反复切页面、复制粘贴和点后台设置的发布流程。给它一篇文章、一段飞书秒记，或一组生活照片；中间的整理、排版、封面、草稿和预览尽量自动完成，最后把结果送到手机上，由你确认。
:::

:::pull-quote
真正的目标不是无人值守地替人发表，而是让一篇内容从素材出发，自动跑到“可以在手机上确认”的那一步。
:::

## 我想自动化的，到底是什么

写作本身不该被自动化替代。观点是否准确、口吻是否像自己、照片是否适合公开，这些判断仍然应该由作者完成。

真正不该反复消耗人的，是写完之后那段机械路：复制正文、调排版、准备封面、上传图片、推草稿、补后台设置、发送预览。它们每一步都不难，但加起来很容易让一篇已经写好的文章停在最后一公里。

我希望最终的体验是：人只负责给出素材、确认内容和看手机预览；其余能稳定复现的步骤，都交给本地流程完成。

:::summary
内容先进入本地工作区；系统自动把它整理成草稿、生成适合公众号的排版和封面，推进到微信公众号草稿并发送手机预览。作者只在内容准确性、公开边界、预览效果和最终发表这些关键点上确认。
:::

## MoonPub 是什么

MoonPub 是一个本地优先的内容发布副驾驶。它不是在线写作平台，也不是绕过平台规则的自动发文机器人。

它把文章和素材留在自己的电脑上，整理为可编辑 Markdown 草稿，再把已经确认过的内容推进到微信公众号草稿。对于后台重复设置和手机预览，它会在用户自己的登录会话中尽量自动完成。

从已有文章开始时，路径是 Markdown、排版、本地预览、微信草稿、手机预览。飞书秒记会先进入 Inbox，再变成可修改的草稿；生活照片也先按真实文件信息进入 Inbox，再整理成需要作者核对的记录。

不同入口的素材不一样，但最后都回到同一个目标：**把内容自动送到一个你可以在手机上判断的状态。**

## 一篇内容怎样跑到手机上

第一步是给出内容。它可以是一篇已经写好的 Markdown、一条飞书秒记，或者一组同一天拍下的照片。

第二步由 MoonPub 在本地完成：把素材整理成草稿，渲染公众号正文，生成封面和本地预览。你可以在这里修改标题、段落、图片和排版，而不是等到公众号编辑器里再返工。

第三步才进入微信。确认后，MoonPub 创建草稿，上传需要的素材，在已登录的本地会话中辅助完成后台重复设置，并把预览发送到手机。

这条流程的价值不在于少输入一条命令，而在于你不再需要把注意力耗在同一批重复操作上。最终需要看的，只有一篇已经排好、已经到达手机的文章。

## 自动化不等于替你做决定

MoonPub 追求的是“自动跑流程”，不是“替人承担责任”。

:::callout
label: 保留给人的确认
素材是否可以发送给 AI、草稿内容是否准确、照片是否适合公开、手机预览是否满意，以及最终是否发表，仍然由作者决定。
:::

微信公众号的扫码、验证码、审核和最终发表不会被绕过。浏览器自动化只在已经登录的本地会话中辅助重复操作；后台页面变化时，相关步骤允许软失败，但不能影响本地草稿和微信 API 草稿创建这条主流程。

这条边界很重要。自动化应该减少机械劳动，而不是把内容、账号和最后决定权一起交出去。

## 谁适合先用起来

MoonPub 当前是技术用户 Beta。它适合已经用 Obsidian 或 Markdown 写作、希望少在公众号编辑器里重复排版的人；也适合有飞书秒记、语音转写或生活照片，想把零散记录稳定沉淀成文章草稿的人。

如果你期待“输入一句话，系统自动写完并自动发表”，MoonPub 不是这个方向。它要做的是更可靠的版本：流程尽量自动，判断始终在人手里。

## 怎么开始

第一次使用，不需要先配置微信，也不必记住全部命令。安装 CLI 并启用 Obsidian 插件后，先打开 `MoonPub 首页`，选择当前文章、最近飞书秒记或当前图片目录中的任意一条入口。

第一轮只要完成这件事就够了：**看到一篇自己能修改、能本地预览的草稿。** 等内容、排版和封面都确认后，再显式推进到微信草稿和手机预览。
