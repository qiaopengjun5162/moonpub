# MoonPub 演示讲稿（约 18 分钟）

配套幻灯片：`docs/demo/index.html`（浏览器打开，`F` 全屏，`←/→` 翻页，`O` 看全部；`Cmd/Ctrl+P` 打印可选「存为 PDF」，每页一屏）。

用法：每节第一行是**要说的那句话**（照着说都行），下面是要点。时间按 18 分钟排，讲快了就省掉「可选」段落。

---

## P1 封面（1 分钟）

**先给结论：这就是一个把你从「排版半小时」里捞出来的小工具。**

- 我是一个人写的，用 Rust，今天讲的是最新版 v0.4.26。
- 不讲代码怎么写，讲三件事：它解决什么问题、怎么用、值不值得你用。
- 一句话概括它在哪停手：**自动化到草稿箱，最后那一下发表永远是人点。**

> 停顿点：如果听众只有 30 秒，就只讲这一页的标题和最后那句。

## P2 它是什么（1.5 分钟）

**三步：你写、它干活、你发表。**

- 第一步你正常写字，Markdown，任何编辑器。
- 第二步它把排版、封面、图片上传、后台四项设置全做完。
- 第三步你在手机上预览，自己按发表。
- 强调「本地跑」：文章和公众号凭证都不出你的电脑。这是设计选择，不是宣传话术。

> 预设提问「那它算自动发布吗？」——不算，也不打算算。原因后面在「边界」那页讲。

## P3 先看效果（1.5 分钟）

**四条命令，不需要公众号账号，也不联网，就能看到成品。**

- 现场可以打开终端跑一遍（真跑，不录屏）：`init` → `new` → `render` → `preview`。
- 指出右侧成品：引言块、正文、结尾总结卡，全是自动的。
- 关键一句：**这四步只读写本地文件，一次网络请求都没有。**

> 实操提示：提前在 `~/moonpub-demo` 留一个干净目录，现场直接 `cd` 进去跑，避免路径出错。

## P4 为什么值得用（2 分钟）

**省下的不是创作时间，是每篇都要重来一遍的重复劳动。**

- 手动排一篇：排版 20–25 分钟 + 封面 5–10 分钟 + 后台设置 3 分钟。
- 用 MoonPub：约 3 分钟，主要时间花在等内容渲染和检查上。
- 更重要的不是单篇快，是**一致性**：十篇文章的样式永远一样，因为都指向同一个主题名。

> 这里可以问听众一句：在座写过公众号的，排版一般花多久？——自然过渡到下一节。

## P5 九步全景（1 分钟）

**从零到草稿箱九步，第一次 10 分钟，之后每篇从第 4 步开始。**

- 只是让听众有个地图，不用逐条念。
- 点一下这个设计：每一步结尾它都打印下一条命令（`next: …`），所以不用背命令。

## P6 演示：装上到建好一篇（2 分钟）

**下载解压就能用，不需要装 Rust 或 Node。**

- 讲 `--version` 能出版本号就等于装好。
- 讲 `doctor` 会直接把「下一条该敲什么」告诉你。
- `init --yes` 建配置，`new "标题"` 建文章骨架。

> 如果现场网络不稳，就跳过下载，直接讲「已经装好的机器」上的命令。

## P7 演示：一篇文章长什么样（2 分钟）

**整篇文章就三块要记：最上面的信息、开头的引言、结尾的总结。**

- 上面三行：`title` 标题、`digest` 摘要（列表里显示的那段）、`theme` 主题。
- `:::intro` 和 `:::summary` 是块语法，会渲染成引言块和总结卡。
- 中间随便写，就是普通段落。
- 明确说：**不用学 Markdown**，记住 `##` 和 `- ` 就够。

## P8 演示：一键出成品（1.5 分钟）

**`render` 一次，产出成品网页和草稿数据；改完再 render 一次。**

- 强调图片会被检查：找不到图会报错停下，不会静默漏图。
- 顺手说一句：成品是本地 HTML，断网也能看。

## P9 排版（1.5 分钟）

**排版不是设计问题，是匹配问题。**

- 31 套主题，只改 `theme` 后面一个词。
- 四张图是同一篇文章：海蓝 / 蓝图 / 青瓷 / 薄雾，字一个没改。
- 给听众两个保底选择：技术文 `blueprint`，通用 `porcelain`。

## P10 封面（1.5 分钟）

**封面是列表里第一眼看到的东西，而它现在是自动生成的。**

- 22 种风格，从文章标题和摘要里长出来。
- 重点讲缩略图那半边：**缩到 96×66 才是真考验**，纯白那张直接糊掉。
- 这条经验对所有做公众号的人都成立，不只是用不用这个工具。

## P11 推送（2 分钟）

**一条命令做六件事，而且每一件都复核过。**

- 逐条念右侧六项，重点在第四项：**它不是点完就算，会重载编辑器确认真的落库**。
- 指出 `media_id`：改稿要用它。
- 最后一句：它停在草稿箱，发表留给人。

> 预设提问「安全吗？」——cookie 会话保存在本地，不经过任何服务器；推的是草稿，不是发布。

## P12 质量（1.5 分钟）

**一个副业项目凭什么让人放心：因为这些东西都有数。**

- 1048 个自动化测试，行覆盖率 84.95%，低于门槛 CI 直接红。
- 五个平台发布，每个资产带 sha256，发版必须过 CI 和资产校验。
- 依赖漏洞零，每周一自动扫。

> 不要说「很稳定」，说数字和门禁。这是技术听众唯一会信的东西。

## P13 优势（1.5 分钟）

**四条，每条都能当场验证。**

- 本地优先 / 人工兜底 / 纯文本可版本管理 / 真的快。
- 「可版本管理」这条对写长文的人最有价值：改坏了 `git checkout` 回去。

## P14 劣势（1.5 分钟）

**这一页我主动讲缺点，因为不讲你也会发现。**

- 只做公众号；多平台在路线里，现在没有。
- 依赖微信后台界面，改版就可能软失败。
- 登录态会过期，要重扫码。
- 没有图形界面，命令行有门槛。
- Beta 阶段，定位是技术用户可试用。

> 主动讲缺点反而增加可信度。补一句：**它适合自己写自己发、每周几篇的人。**

## P15 和别的做法比（1.5 分钟）

**它不是排版编辑器的替代品，它管的是「从稿子到草稿箱」这一段。**

- 手动 / 秀米 135 这类编辑器 / Notion 导出 / MoonPub，四种干法。
- 关键差异：内容不上传别人服务器、后台设置自动做完并复核。
- 诚实说代价：只支持公众号，要会用命令行。

## P16 规划（1.5 分钟）

**路线公开在仓库里，硬边界写在文档里。**

- v0.5 插件化（发布器 / 渲染器 / 封面主题做成接口）
- v0.6 Obsidian 插件正式化
- v0.7 多平台：先静态博客，再 WordPress，再 Ghost
- v1.0 商业化只是草案，核心免费不变
- 硬边界：不托管凭证、不代发、不绕审核

> 如果有人问「会不会收费」，照这条答：核心 MIT 免费，付费层只是方向草案，未承诺。

## P17 现在就能试（1 分钟）

**不需要注册，不需要公众号账号，五分钟能看到成品。**

- 给仓库地址。
- 三条命令就能看到东西：init / new / render。

## P18 收尾（30 秒）

**谢谢，随便问。**

- 留一句最小行动号召：今天回去跑一遍 `init --new--render--preview`，就知道值不值得用。

## 可能的提问与答法

| 问题 | 怎么答 |
| --- | --- |
| 会不会被微信封？ | 它用的是你自己的账号和浏览器会话，走的是后台正常操作，不刷接口、不群发、不自动发表。风险和你手动排版发布一样。 |
| 为什么不做网页版？ | 凭证不出本地是硬约束。做网页版就得托管密钥，那是这个项目明确不做的事。 |
| 支持小红书/知乎吗？ | `cards` 能切竖版卡片，但正式多平台发布在 v0.7，只接有官方 API 的平台。 |
| AI 写稿能代替我吗？ | 那些命令要你自己的模型 key，且结果要人工审。它们不是核心路径。 |
| 我不用命令行怎么办？ | 现在是门槛，Obsidian 插件（v0.6）就是为了这个。 |
