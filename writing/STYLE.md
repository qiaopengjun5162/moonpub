# 文章标准

这份文件约束 `writing/articles/` 下每一篇的标题、骨架和证据要求。
不符合的稿子不发。宁可少写一篇，不写一篇让人不知道在说什么的。

## 一、标题公式

**必须同时满足三件事**：说清是什么项目、说清这篇讲什么、带一个具体数字或结论。

```text
用 Rust 写公众号发布工具（第 N 篇）：<具体发现 + 数字>
```

反例（不要这样写）：

| 坏标题 | 为什么坏 |
| --- | --- |
| 三个半小时，二十次尝试 | 不知道在做什么项目，也不知道做成了没有 |
| 本地全绿，CI 全红 | 谁的全绿？什么项目？读者无从判断 |
| Vue 不认 JS 点击 | 像一篇前端科普，和公众号发布工具无关 |

正例：

| 好标题 | 好在哪 |
| --- | --- |
| 用 Rust 写公众号发布工具（第 1 篇）：第一个提交塞了 4967 行，四个月后 lib.rs 只剩 131 行 | 项目、事件、两个可验证的数字 |
| 用 Rust 写公众号发布工具（第 2 篇）：单日 87 次提交，三个半小时我切了七次技术栈 | 项目、规模、真实难度 |
| 用 Rust 写公众号发布工具（第 6 篇）：覆盖率 71.99% 是假的，核心链路只有 1.6% | 项目、反直觉结论、具体数字 |

标题长度控制在 64 个字符内（公众号上限），中文按 1 个字符算。

## 二、固定骨架

顺序不能变，缺一节就不发。每一节都要有实际内容，不许写"本节略"。

```markdown
---
title: 用 Rust 写公众号发布工具（第 N 篇）：<标题>
theme: geek-black
digest: <30–110 字，说清这篇的结论>
wechat_author: Paxon Qiao
---

> **项目**：MoonPub —— 用 Rust 写的公众号发布副驾驶
> **仓库**：github.com/qiaopengjun5162/moonpub
> **本篇**：第 N 篇 · <一句话主题>

## 前言

三到五句。回答三个问题：这篇讲什么、为什么值得看、读完能拿走什么。
第一次出现的专有名词在这里解释。

## 背景

项目是什么、当时处在哪个阶段、遇到了什么具体麻烦。
要给出时间坐标（哪一天、第几次提交）和规模坐标（多少行、多少次提交）。

## 截图

至少一张真实截图，配图注说明"这张图证明了什么"。

3. **提交锚点**：`git show <hash>` 能看到当时的改动

## 三、证据等级

每写一句话先问：这句话的证据在哪。

| 等级 | 含义 | 能不能写进文章 |
| --- | --- | --- |
| A | 我刚跑过命令，输出在文里 | 能，且要贴输出 |
| B | 仓库里的代码/文档能直接查到 | 能，要给 `文件:行号` |
| C | git 历史里有提交，我没复核内容 | 能，但要写"提交信息称" |
| D | 我记得是这样 | **不能**，先去验证 |

写作时最常见的错误是把 D 当 A 写。上一版文章 01 就写错了两处：

- 说单日 87 次提交发生在 06-10，实际在 06-11
- 说 5 份 HTML 转义里"3 份不转义单引号"，实际是 **4 份**（只有 `cover.rs` 转了）

两处都是凭记忆写的。所以现在有这条规矩。

## 四、数字规范

1. 所有数字标注**测量时间**。项目在动，数字会漂。
2. 不复算就不写。写完自己去跑一遍文章里的命令。
3. 数字变了就补新值，不改旧值——旧值是当时的真相。
4. 覆盖率、行数这类会持续变化的，写成"截至 2026-10-30"。

## 五、图片规范

命名、脱敏清单见 [`assets/README.md`](assets/README.md)。

补充三条：

1. 图注必须写"这张图证明了什么"，不能只写"截图"
2. 一张图只证明一件事
3. 终端输出用代码块，不要截成图——代码块可以复制，图不能

## 六、封面规范

封面和公众号标题是两件事。公众号标题负责被搜到（可长可带系列前缀），封面负责在信息流里被看懂（必须短）。

1. **主标题 ≤22 字，一行读完。** 超出会被截断成省略号，等于白写。
2. **副标题 ≤34 字，说完这篇的结论。** 没有副标题的封面等于只有标题，读者不知道文章值不值得点。
3. **`cover_tag` 固定格式 `MOONPUB · NN / 07`**，让读者一眼看出这是系列第几篇。
4. **`theme` 全系列统一 `geek-black`。** 换风格等于换品牌，不要逐篇变。
5. **主副标题显式写进 frontmatter**，不要依赖从长标题里自动拆分——自动拆分对「单日 87 次提交」这类短标题没问题，对含多标点的标题会切错位置。

```yaml
theme: geek-black
cover_subtitle: 三个半小时我切了七次技术栈
cover_tag: MOONPUB · 02 / 07
```

主标题字号按字数自适应（`src/cover.rs` 里分四档：≤8 字 78px、≤11 字 64px、≤15 字 56px、其余 48px），保证每张封面视觉重量一致——7 个字的标题和 15 个字的标题不应该看起来一样小。

生成后**必须亲眼看图**，不能只看 HTML：

```bash
moonpub cover --article writing/articles/<文件>.md --screenshot
```

## 七、发布前自检

```bash
# 1. 标题与 digest 长度
head -6 writing/articles/<文件>.md

# 2. 渲染成微信 HTML（会校验 frontmatter）
moonpub render --article <文件>

# 3. 排版体检
moonpub layout-audit --article <文件>

# 4. 图片路径是否存在
grep -o '](\.\./assets/[^)]*)' writing/articles/<文件>.md
```

四项全过才算成稿。
