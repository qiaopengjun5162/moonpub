# MoonPub 推荐工作流

这份文档只回答一个问题：

**如果我是第一次使用 MoonPub，我现在应该走哪条路径？**

不要先从全部命令开始看。现在更推荐的做法是：如果你在 Obsidian 里工作，先打开 `MoonPub 首页工作台`，再根据你的内容来源，选择下面三条主路径之一。

如果你现在要的不是“完整工作流说明”，而是“第一次到底先点哪里、先跑什么最不容易迷路”，先看 [FIRST_RUN_WALKTHROUGH_ZH.md](FIRST_RUN_WALKTHROUGH_ZH.md)。

## 先判断你属于哪类用户

### 路径 A：你已经有一篇 Markdown 文章

适合你，如果你：

- 平时就在 Obsidian / Markdown 里写文章
- 已经有完整草稿
- 主要想把文章排版后发到公众号

### 路径 B：你是从飞书秒记 / 语音记录开始

适合你，如果你：

- 内容还不是文章，而是一段转写
- 想先把素材整理成草稿
- 想先确认内容，再推进到公众号

### 路径 C：你是从生活照片开始

适合你，如果你：

- 手机里已经有一组想保留下来的照片
- 想先把照片整理成草稿，而不是直接丢到相册深处
- 想先确认记录方式，再决定是否继续推进到公众号

---

## 路径 A：已有文章 → 本地预览 → 微信草稿

这是当前最基础、最稳定、最容易理解的主路径。

### 第 1 步：创建或准备文章

```bash
moonpub new "我的第一篇文章"
```

或者直接使用你现有的 Markdown 文件。

### 第 2 步：先做本地渲染和预览

```bash
moonpub render Articles/drafts/我的第一篇文章.md
moonpub preview Articles/drafts/我的第一篇文章.md
```

这一步只处理本地文件，不需要微信凭证。

你要确认的是：

- 标题、摘要、段落是否正常
- 排版主题是否合适
- 图片、引用、代码块是否正常

### 第 3 步：如果需要，生成封面

```bash
moonpub cover Articles/drafts/我的第一篇文章.md --style literary --screenshot
```

### 第 4 步：推到微信公众号草稿

```bash
moonpub push Articles/drafts/我的第一篇文章.md --render
```

前提：

- 已配置 `WECHAT_APPID`
- 已配置 `WECHAT_SECRET`
- 当前机器 IP 已加入微信白名单

### 第 5 步：后台辅助配置并预览发送

```bash
moonpub configure
```

它会尝试完成：

- 原创
- 赞赏
- 留言
- 创作来源
- 预览发送到手机

### 第 6 步：微信后台人工确认并发布

MoonPub 的产品边界始终是：

- 帮你把内容推进到“可发布状态”
- 不代替你做最终发表确认

---

## 路径 B：飞书秒记 → 草稿 → 预览 → 微信草稿

这是当前最值得继续主推的第二条主路径。

它不是“直接发”，而是：

**先把素材整理成草稿，再由你确认是否继续。**

### 推荐默认模式：保守路径

```bash
moonpub --articles "<Obsidian 路径>" intake feishu --latest --draft --preview
```

或者：

```bash
moonpub --articles "<Obsidian 路径>" intake feishu --minute-token <token> --draft --preview
```

这条路径会做 4 件事：

1. 把飞书秒记导入 `Inbox/Feishu/`
2. 生成可继续编辑的文章草稿
3. 渲染本地 HTML
4. 停下来等你确认

### 你接下来怎么做

草稿生成成功后，优先看这 3 个后续动作：

- `edit_path`：继续改稿、补图、去 AI 味
- `preview_command`：继续检查本地排版
- `push_command`：确认后再推微信草稿

推荐顺序是：

1. 先改稿
2. 再看本地预览
3. 最后推微信草稿

### 快速模式：你明确知道自己要直接推进

```bash
moonpub --articles "<Obsidian 路径>" intake feishu --latest --draft --push
```

只有在这几种情况下才建议用：

- 你已经很熟悉这条链路
- 你确认这次内容不需要多轮修改
- 你愿意直接进入微信草稿后再检查

### 飞书路径进入微信草稿后

后半段就和普通文章完全一样：

```bash
moonpub configure
```

然后：

- 手机预览
- 后台人工确认
- 发布

---

## 路径 C：照片素材 → 草稿 → 预览 → 微信草稿

这条路径和飞书一样，也属于：

**先把素材整理成草稿，再由你确认是否继续。**

### 推荐默认模式：保守路径

```bash
moonpub --articles "<Obsidian 路径>" intake photos photos/day1 --draft --preview
```

或者：

```bash
moonpub --articles "<Obsidian 路径>" intake photos photos/day1 photos/day2 --draft --preview
```

这条路径会做 4 件事：

1. 把一组真实照片归档到 `Inbox/Photos/`
2. 生成可继续编辑的文章草稿
3. 渲染本地 HTML
4. 停下来等你确认

### 你接下来怎么做

照片草稿生成成功后，推荐顺序和飞书类似：

1. 先看草稿是不是忠实记录了这组照片
2. 再看本地预览
3. 最后再决定是否推微信草稿

### 什么时候适合走这条路径

典型场景：

- 跑步、散步或旅行后拍的一组照片
- 想把“这一天发生了什么”先留成草稿
- 不想让照片最后只停在相册里

---

## 什么时候用哪条路径

### 用路径 A，如果你已经有完整文章

典型场景：

- 你在 Obsidian 里写好了文章
- 你在本地已经整理好了结构
- 你主要关心排版和发布

### 用路径 B，如果你现在只有素材

典型场景：

- 跑步后的语音感想
- 飞书妙记转写
- 临时记录的思考
- 会议/散步/读书碎片

### 用路径 C，如果你现在主要想整理照片

典型场景：

- 手机里一组同一天的生活照片
- 想先按真实信息把照片沉淀成草稿
- 后续再慢慢补充当时的感受和上下文

---

## 当前最推荐的第一次体验顺序

如果你是第一次接触 MoonPub，建议按这个顺序：

1. 先跑路径 A 的本地体验，确认你喜欢它生成出来的文章和排版
2. 如果你装了插件，先打开 `MoonPub 首页工作台`
3. 再试一次飞书路径，确认你接受“素材 → 草稿 → 预览 → 推送”这个节奏
4. 如果你有生活照片素材，再试一次照片路径
5. 最后再进入真实公众号发布

原因很简单：

- 路径 A 最容易理解
- 路径 B 最能体现后续产品潜力
- 路径 C 说明 MoonPub 已经开始具备多输入源形态
- 插件首页已经开始承担统一入口角色
- 三条都走通后，你就能更完整理解 MoonPub 的产品形态

---

## 记住这条产品原则

MoonPub 当前不是“自动发文机器人”。

它当前最合理的理解方式是：

**一个本地优先的内容发布副驾驶。**

它擅长的是：

- 帮你整理内容
- 帮你生成草稿
- 帮你完成排版
- 帮你推进到微信草稿
- 帮你减少后台重复点击

但最终内容是否合适、是否发布，仍由你自己确认。
